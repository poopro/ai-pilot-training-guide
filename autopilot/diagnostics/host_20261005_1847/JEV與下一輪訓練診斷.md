## 現在最重要的結論

先修正本地評估與 Host 的落差，再比較 SAC 或上層模型。這場官方 Host 回放是你當 P1／藍方，內建程式當 P2／紅方；你的啟動紀錄使用 `player.py --guide`，是純引導器，沒有載入 SAC 修正模型。

這場確實有命中：紅方 HP 180 → 55；我方 HP 保持 180。紅方沒被擊落是因為 Host 計入的攻擊只有 125 tick／60 = **2.083 秒**，還差 **55 tick／0.917 秒**達到累積三秒。規則是可中斷後累積三秒，不是必須連續三秒。

更重要的是：以 CSV 的位置、機鼻姿態逐筆重算，偏差 ≤1°、距離 500–3000 呎的 125 筆，與實際扣血逐筆完全吻合；使用目前本地的 ≤2° 則得到 763 筆／12.717 秒，與扣血相差 638 筆。這是本場實測，不足以斷言所有官方版本都用 1°。規則文字和圖示可能存在全錐角／半角的解讀差異，應向主辦方核對。訓練可保守要求偏差小於 1°，例如以 0.8° 為瞄準目標，這仍位於公告的 2° 範圍內。

## 一、JEV 到底做了什麼

你提供的專案使用 **TypeSafe Jev**，不是 Meta JEPA；先前將縮寫猜成 JEPA 的說明不適用於這個連結。Jev 對狀態回答受限的選項、分數或真假判斷，不是現成的戰機駕駛員。[TypeSafe 模型說明](https://docs.typesafe.ai/introduction)

`jev-drone` 的主要示範是四旋翼追蹤地面目標、避障：500 Hz 幾何飛控、50 Hz 引導與安全層、約 2.5–3 Hz Jev 戰術判斷。Jev 不直接接管每個飛行控制 tick。[專案架構](https://github.com/RomanSlack/jev-drone)

原版 `tactics.py` 使用 `TypeSafeClient` 呼叫 `jev-latest`；TypeSafe 官方快速開始提供外部 API 端點。這份倉庫不是 Jev 的本機權重或訓練程式；不能把安裝範例當成已取得離線模型。[tactics.py](https://github.com/RomanSlack/jev-drone/blob/main/tactics.py)、[TypeSafe API](https://docs.typesafe.ai/introduction/quickstart)

你的規則書 PDF 第 4 頁規定封閉網路、不得外部連線參賽，所以原版 API 呼叫不能直接帶進比賽。可借用「受限策略選項 → 本機快速飛控」的設計；若要用 Jev 本身，必須先取得確實可離線執行的版本並確認規範。這次查到的專案沒有提供這種部署證據。

## 二、是否比規則式或 SAC 更好

| 方法 | 白話說明 | 如何判斷是否值得使用 |
| --- | --- | --- |
| 純規則引導器 | 人寫好接近、追蹤、恢復等控制方法；不需要訓練模型 | 作為所有實驗的固定基準 |
| 純 SAC | 由獎勵學習飛行控制；SAC 是訓練算法，不等於規則式 | 必須另外實作純 SAC 基準，不能拿目前的 residual 版本冒充 |
| 引導器＋SAC 修正 | 保留引導器，SAC 只學有限的修正量 | 正是目前 `combat_v3` 的訓練架構；新模型必須勝過零修正引導器 |
| 慢速策略模型＋快速飛控 | 上層選策略，下層維持 60 Hz 控制 | 與具備相同策略選項的規則上層公平比較，測量收益和延遲 |

沒有證據保證兩種混合方法更好。JEV 作者也將成功避障示範標為單次結果，早期三種子比較沒有改善；不能推論會改善 F-16 空戰。[實驗限制](https://github.com/RomanSlack/jev-drone#results)

本地既有保留測試中，對 `duel` 的純引導器和 SAC 都是 6/20 擊落、20/20 存活，因此預設發布仍是純引導器。**這些數字使用舊本地 2° 裁判和隨機起始航向；發現本場 Host 判定落差後，更不能把它們當成官方擊殺率。** 舊報告和模型保留作為歷史基準。

## 三、紅方為什麼不太反擊

官方內建 P2 的 `player2_runtime.log` 明寫：`Random level-flight PID controller ready (SAC disabled)`。本場出現 Straight、Turn Left、Turn Right；紅方最大滾轉約 59.8°，確實有轉彎，但未對你造成扣血。它是連線驗證對手，不能代表正式競賽隊伍。

本地也有三種不同對手：

| 對手 | 目前程式行為 |
| --- | --- |
| `easy` | 小幅左右轉彎、保持高度，不主動追擊 |
| `maneuver` | 更大的轉彎、保持高度，不主動追擊 |
| `duel` | 追蹤我方；在接近威脅時暫時閃避，之後重新追擊 |

`mixed` 的最後階段仍有 65% 是前兩種、35% 是 duel。容易的對手適合起步，不能用它們的高擊殺率當成完整空戰能力。下一版先加入確實會追擊的對手池，再逐步引入固定舊策略作為對手；強度和攻擊結果都要量測。

擊落是幾何條件達標後由裁判自動判定，不需要加射擊或飛彈按鍵。也不應去改官方 Host 內建 P2 或正式裁判。

## 四、起始位置與規則的差別

規則書 PDF 第 7 頁／印刷第 6 頁：3000／6000／9000 呎、初始高度 10000–20000 呎、340 節。圖 3 畫的是**側向分開、兩機反向的平行航向**，不是一開始就在後方瞄準，也不是正面互衝。

![官方圖示及初始條件](<E:/ai_pilot/autopilot/diagnostics/host_20261005_1847/official_page_7.png>)

本場 Host 第一筆：兩機航向約 303°／123°，機鼻對彼此約 90.48°，相對隊形與圖示相符；高度約 15328 呎，IAS 約 339.85 節。第一筆已是 0.033 秒，不能要求它精確等於 reset 時的 340 節。

CSV 經緯度以短距離切平面方法估算的分隔約 **8199 呎**，與文字列出的三個距離不完全一致。這是外部重算，不是讀到 Host 內部的距離欄位；尚未取得該回合初始化選項或 Host 距離算法，需核對來源與版本。不能據此偷偷改比賽資料或把 8199 呎視為官方新規則。

目前 `combat_v3/env.py` 即使選 `scenario='official'`，stage ≥1 仍隨機抽兩機的相對方位和我方航向。它只涵蓋了公告的距離／高度／空速範圍，**不是完整重現圖 3 的隊形**。這個名稱會讓評估被高估為正式條件，下一版應拆成：

1. `official_fixture`：依圖 3 的隊形、指定三種距離初始化，使用 Host 收到的狀態做核對。
2. `randomized_training`：保留各種相對航向，用於增強泛化；報告明寫是隨機訓練場景。
3. `host_record_fixture`：重播本場初始狀態供回歸診斷；已看過的紀錄屬於開發資料，不能當全新的獨立測試。

## 五、下一輪訓練的實際順序

1. **保留現有可用引導器。** 另開新版實驗，保留 v2/v3、完整 model/replay 和來源校驗。原無人值守 20 萬步預算已結束；本次沒有自動追加。
2. **先完成 Host 相容測試。** 分開記錄公告文字 2° 與本場 Host 1° 的結果，用更多新回合、靠近距離邊界的樣本核對。報表以真正 HP 變化／正式裁判為準，勿把 `Score_Kills=2.083` 當成擊落兩架。
3. **對齊初始化。** 測到實際 3D 距離、兩機航向差 180°、側向分隔、同高度（依本場 Host）和 reset 空速，再訓練；不只檢查 config 寫了什麼。
4. **先改善純引導器的精準追蹤。** 遠距離做攔截，進入 500–3000 呎後避免超越目標、穩定機鼻誤差。以 0.8° 為保守目標，保留高度恢復、失速保護和過 G 限制。先不加語言模型。
5. **再練 SAC 的小幅修正。** 獎勵給真正有效攻擊時間，對 1° 內的精準追蹤提供平滑、有限的進度獎勵；維持被擊落／墜機懲罰，記錄過 G、最低高度、接近速度和失敗原因。單純加大 kill bonus 不會修正錯誤裁判。舊 replay 來自不同場景／獎勵，不能無檢查沿用；現有 trainer 也會拒絕來源變更後續訓。
6. **由弱到強，但以強對手選模型。** 前期用容易目標確認飛控，後期提高會追擊的對手比例，加入不同固定對手和舊策略池。開發測試與全新保留種子分開；不要用先前 20262000–20262019 的已看過測試重新調參後再稱為獨立成績。
7. **小批次保存、評估後再延長。** 新預算可先做 5–10 萬步試驗，每 1–2 萬步同條件比較純引導器與 SAC；此數字只是試驗設計，沒有保證會學好。看擊殺率、正式／本地比分、存活、攻擊時間、失敗原因，而不是只看 loss。只有可靠改善才替換部署版本。
8. **最後做上層策略消融。** 先讓規則上層在追擊、控距、保持能量、脫離、恢復等相同選項中選擇，再加入本機的小模型選項器作比較。建議每 1–3 秒或事件觸發一次，背景非同步；舊指令、逾時與低信心回到已驗證引導器，快速飛控仍每秒 60 次。策略切換應保留最小持續時間，避免左右反覆。

所有控制器與上層模型只能接收規定的我方 20 項＋敵方位置／速度 6 項，或由它們計算的資訊。敵方真實姿態、HP、腳本類型與其未來操作，只能由測試裁判／離線分析讀取，不能偷渡到部署輸入。
