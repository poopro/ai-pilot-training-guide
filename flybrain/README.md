# flybrain：讓果蠅全腦連結體當一次「AI 飛行員」（研究分支）

> 放在 `E:\ai_pilot\flybrain\`，**不改動** `jepa_brain\`、`campaign_2026\` 或官方資料夾裡任何檔案。

## 0. 先講清楚：這是什麼、不是什麼

- **是**：把真實果蠅的全腦連結體（FlyWire v783，138,639 個神經元、約 1,509 萬條突觸連線）當成一個**固定不動的神經網路**，把比賽的合法觀測值轉成感覺神經元的放電，讓整個腦用 LIF（leaky integrate-and-fire）模型跑 80 ms，再從 1,299 個下行神經元（DN，腦通往身體的出口）讀出「這個腦想做哪個戰術」。
- **是**：一個可以看、可以玩、可以量測的實驗。右邊的視覺化會讓你直接看到哪些神經元被哪個特徵點亮。
- **不是**：果蠅「學會了飛行」。連結體的權重不會被訓練，訓練的只有它前後的薄薄一層介面（編碼 / 讀出）。這在機器學習裡叫 reservoir computing（固定的大型動態系統 + 可訓練的讀出層）。
- **不是**：現成的勝率提升。以你現有的 PURSUE / 規則式 + SAC + JEPA，沒有任何理由預期果蠅腦「直接」比較強。它最現實的定位是研究分支，以及一個可能的另類特徵 / 戰術選擇器。
- **10/17 結論（兩段，詳見 6.6 與 6.12）**：(1) 第一版（離線隨機探索資料 + 每 0.33 秒換戰術）最好 55 勝 17 敗，輸給 `base_t3` 的 64–8。(2) 改成「分支反事實標籤 + 鎖定戰術 2 秒的選項戰術員」之後，在 360 場與 `base_t3` 同種子配對的對戰（新種子 144 場、全新對手 216 場，設定凍結）裡 DN 版 346–14、`base_t3` 235–125，其中只有 DN 贏 116 場、只有 `base_t3` 贏 5 場；鏡像局從約 4 成變成 24–0。**但進步來自標籤方法，沒有腦的 54 × 7 線性模型同樣有效**；而且只在本地 judge、腳本對手上驗證過。
- **10/19 更新（詳見 6.15–6.22）**：(1) 在三批沒用過的種子（1010000、1030000、1090000）上，疊上選項戰術員的 tuned 追擊對腳本對手池是 207–209 勝／216（plain tuned 158-58、`base_t3` 137-79），0 場被擊落。(2) **但「完全不看狀態的隨機戰術」也有 141／162 勝**：多數勝場來自「近距離不要一直純 PURSUE」（打破鏡像僵局），學習的貢獻在 lead 型對手、平均分差，以及對手也會戰術的對局（隨機 10.9%，學到的頭 50–70%）。(3) 連結體沒有獨立貢獻的證據；果蠅 DN 版和 54 × 7 ridge 總勝場相同，且在 lead 型對手上可重現地較弱。(4) 可攜單檔 `portable\fighter_opt.py`（numpy 即可，單次 `act()` 約 0.25 ms，與 harness 逐場一致）已就緒，**但沒有 Host 實機驗證**。(5) 推薦：預設 ridge v1（`opt_ridge:tuned`），對會戰術切換的對手改用 MLP v4（`opt_mlp:tuned`）。
- **紅線**：**沒有在 ≥ 60 場成對對戰（同種子、同距離、同方位、同高度，與 PURSUE 比較）中勝出之前，絕對不要取代正式比賽用的控制器。**

## 2. 怎麼配合比賽規則

| 比賽規則 | 這裡怎麼做 |
|---|---|
| 輸入：Host 每幀給 20 個本機狀態 + 6 個目標狀態 | 只用這些合法值（經 `jepa_brain.feats.features` 整理成 27 個數字，沒有偷看任何別的東西） |
| 輸出：4 個控制量（aileron / elevator / rudder / throttle），經 UDP | **果蠅從不碰這 4 個值。** 它每 20 個 tick（3 Hz）只挑 8 種戰術之一，實際的 60 Hz 控制仍由凍結的控制器產生（含速率限制、9 G 保護、地面恢復），所以封包格式 / 60 Hz 都不變 |
| 只能在本機推論 | 連結體資料下載一次放在本機，比賽時不需要網路 |
| 高度安全 | 戰術遮罩：離地 < 2,500 呎禁 LOW_YOYO；< 1,800 呎再禁 BREAK_IN / BREAK_OUT / HIGH_YOYO / LOW_YOYO |

27 個特徵怎麼變成神經元放電（`flybrain/pilot.py`）：

- **推拉編碼**：特徵值高於平均 → 激發**右側**那組神經元；低於平均 → 激發**左側**那組（跟果蠅兩隻眼 / 兩根觸角的做法一樣）。每組 k = 20 個神經元，最大 100 Hz 的 Poisson 輸入。
- **哪類特徵接哪類神經元**（這是設計選擇，不是生物學事實）：
  - 敵機幾何（距離、接近速度、角度…）→ 視覺投射神經元 LC / LPLC / LLPC / LPC（偵測逼近與追蹤目標的細胞）
  - 本機姿態與動力（滾轉、攻角、G 值…）→ Johnston 氏器的風 / 重力神經元 + 頭部剛毛
  - 任務狀態旗標 → 味覺神經元
  - 刻意**避開**嗅覺 / 溼度 / 溫度神經元：它們會讓約 1 萬個神經元連鎖爆發（雪崩），DN 輸出飽和
- 每個池子再用「3 步反向興奮性影響力」只留影響 DN 最大的前 70%。
- **讀出**：每個決策讓腦跑 80 ms 模擬時間（狀態延續到下一個決策），數 1,299 個 DN 的放電數，做平方根轉換（Anscombe），再用線性 Q 讀出層選戰術，並加遲滯（margin）避免亂跳。

## 3. 訓練

連結體不訓練。要訓練的只有編碼增益和讀出層。

**Stage A：離線 ridge（快、便宜、只是診斷）**

```powershell
python replay.py  --data ..\jepa_brain\runs\collect01\data --out cache --max-games 60 --device cuda
python train_q.py --cache cache --out readout.npz
```

- `replay.py` 把你已經收集的對戰（隨機探索戰術，所以不同戰術的比較沒有偏差）一幀一幀「放給果蠅腦看」，存下 DN 放電。
- `train_q.py` 用 Monte-Carlo 回報當目標，擬合 `Q_a = V(x) + A_a(x)`，每 4 場留 1 場當驗證，並**另外拿同一個讀出層直接吃 27 個原始特徵當對照組**。如果果蠅腦沒有贏過這個對照組，它就只是一個很貴的隨機特徵映射。
- 離線指標（R²、貪婪動作一致率）**不等於**對戰實力。
- 預設正則化 `--lam-v 30000 --lam-a 10000` 是我用 3 場留出對戰挑的（1,299 個 DN 特徵配幾千筆決策，弱正則化會嚴重過擬合：留出 R² = −0.36）。所以留出指標略偏樂觀；資料變多後請重新掃一次。

**Stage B：閉迴路成對評估（真正的考試）**

```powershell
python fly_eval.py --readout readout.npz --n 6 --device cuda --workers 1 --out runs\fly01
```

- 用你的 `jepa_brain.rollout.play_game`，同種子、同距離 / 方位 / 高度，**PURSUE 與果蠅各打一次**，產生成對比較表。種子從 700000 開始（訓練資料用的是 600000+）。
- 要下結論至少 60 場成對對戰（每種對手 10 場以上）。6 場只是冒煙測試。

**Stage B'：直接放進你的 `rollout_bfm` 基準（10/17 新增，建議用這個）**——`fly_bfm.py` 把果蠅當成 `fly_t3` 這個 arm，與你的 `base_t3` 用同一份對手、種子、距離與高度設定：

```powershell
python fly_bfm.py --readout ro\dn_g99.npz --prune-cache cache480 --backend numba --arms fly_t3 --n 12 --seed0 950000 --workers 2 --pursue-bonus 0.5 --out runs\val_dn_b5
```

`--pursue-bonus` 是加在 Q(PURSUE) 上的偏置：果蠅只有在預期優勢超過這個值時才會偏離 PURSUE。`--feat` 改用不經過腦的 27 個原始特徵讀出層（對照組）。

資源估計（CPU 與 GPU 實際速度請看你自己的 `selftest.py` 輸出，我這裡只量過 2 核心 CPU 容器）：每場 300 秒 = 900 個決策。

## 5. 我實際跑出來的結果（誠實版）

**Stage A（12 場舊對戰、9,889 個決策；9 場訓練 / 3 場留出）：果蠅沒有比對照組好，兩者離線都看不到可靠訊號。**

| 讀出層的輸入 | 留出 R² | 貪婪動作 = 記錄動作的比例 | 這些決策的平均回報 − 全體平均 |
|---|---|---|---|
| 1,299 個 DN 放電（果蠅腦） | −0.05 | 21% | +0.049 |
| 27 個原始特徵（對照組，不經過腦） | +0.01 | 19% | +0.053 |

- 回報標準差約 0.3–0.5，所以 +0.05 的差距很小；而且同一場內的決策高度自相關，這個差距不能當成顯著。
- 資料裡 47% 的動作是 PURSUE（不是均勻隨機），12 場也太少。這個診斷的結論只能是「沒有證據顯示果蠅腦比直接用特徵更好」，不是「果蠅腦不可能有用」。
- 1,299 個 DN 裡，只有 **195 個**在超過 2% 的決策中有放電；實際可用的讀出維度遠小於 1,299。
- 特徵「攻擊累積」與「1° 鎖定」在這 12 場裡幾乎恆為 0，等於沒有輸入。

**閉迴路初測（10/17，7 場成對對戰；只能當方向，不是統計結論）**：用上面那個讀出層（`readout.npz`）讓果蠅選戰術，與「凍結控制器 + 永遠 PURSUE」基線打同樣的種子 / 距離 / 高度。果蠅 1 勝 6 敗，基線同一批 4 勝；果蠅有 2 場被紅方擊落，基線這批沒有被擊落（有 1 場碰撞）。原因與離線診斷一致：讀出層幾乎等於隨機選戰術，選到放棄位置的戰術就會被打。
（第一次測試時 `fly_eval.py` 預設 dt = 0.5 ms，但讀出層是用 dt = 1.0 ms 的資料訓練的，不一致；已把預設改成 1.0（`--dt`），用剪枝版重跑同樣 7 個種子，結論相同。）
基線 60 場（seed 700000+，每種對手 10 場）：breaker 10/10、level 10/10、mix 10/10、lag 7/10、lead 4/10、guide 2/10，共 43/60；多數是時間到靠優勢分數判勝（timeout），不是擊殺。這個基線**不是**你完整的 SAC / JEPA 堆疊；要和你真正準備上場的版本比，請用 `fly_eval.py`（不加 `--no-baseline` 時基線是 jepa_brain 的 PURSUE-only）或自己改成你的控制器。

**DN 在追蹤什麼**（`python analyze_dn.py`，結果寫在 `dn_feature_corr.md`；Spearman 相關）：例如距離 ↔ DNpe056·R (+0.52)、DNp34·L (+0.49)；機鼻偏角 ↔ DNp05·R (−0.46)、DNp73·R (−0.42)；滾轉 sin ↔ DNge036·L (−0.62)、DNge037·R (−0.59)。注意：這主要反映「我把哪個特徵接到哪一池感覺神經元」加上特徵彼此相關，**不是**在生物學上發現了什麼；也不要把 DN 名字直接當成它的功能。

**速度**（2 核心 CPU 容器，dt = 1 ms）：每個戰術決策 0.135 秒（3 Hz 的預算是 0.333 秒），一場 300 秒 ≈ 2.0 分鐘腦運算；1 秒生物時間 ≈ 1.4 秒實際時間。GPU 沒有量過。

**驗證過（在 Linux 容器、2 核心 CPU）**

- **LIF 實作 vs 原作者 Brian2**：同一組刺激（100 個視覺投射神經元，150 Hz，1 秒），逐神經元放電數的相關係數：dt = 0.1 ms 為 0.997（DN 0.992）、dt = 0.5 ms 為 0.996（DN 0.973）；總放電數比 Brian2 多約 4%（21.7k vs 20.8k）。
- **雪崩**：嗅覺 / 溼度 / 溫度輸入會讓約 1 萬個神經元連鎖放電；改用 JO / 視覺投射 / 味覺池 + 影響力過濾後，每個窗口活躍神經元約數百個，DN 約 23–26% 有放電。
- **整合**：在真正的 JSBSim 競技場（`play_game`）跑過 `--passive`（旁觀）與 `q` 模式（果蠅選戰術）的短場，介面、種子、紀錄都通。測試中抓到並修掉一個 bug：`q` 模式未開 `--record` 時 `observe()` 回傳值拆包錯誤。這些短場只證明「管線能跑」，沒有任何勝率意義。

**沒驗證**

- GPU 速度、Windows 上實際執行（只在 Linux 容器跑過）。
- dt = 1.0 ms（replay 預設）沒有和 Brian2 對過；只對過 0.1 與 0.5。
- 閉迴路勝率：沒有結論，見第 3 節 Stage B。
- 比賽機器上的延遲：2 核心容器的決策 0.135 秒，但含物理模擬的整場測試約接近即時，餘裕不大；請在比賽用電腦上用 `selftest.py` 重量。

## 6. 加速到接近 60 Hz、砍神經元、懲罰、訓練對手（10/17 補充）

**6.1 「60 Hz」要看是哪一個**：比賽的 60 Hz 是輸出頻率，凍結控制器本來就做到了。果蠅現在每 3 Hz（20 tick）選一次戰術，每次只模擬 80 ms 的腦時間。想讓腦「即時」跟著比賽跑（腦時間 = 比賽時間），每個 tick（16.7 ms）要算 17 個 1 ms 步。我在 2 核心 CPU 容器量到：

| 腦 | 引擎 | 神經元 | 每個 60 Hz tick（17 步） | 預算 16.7 ms |
|---|---|---|---|---|
| 完整 | torch | 138,639 | 平均 25.4 ms（p95 35.8） | 跑不動 |
| 完整 | numba | 138,639 | 平均 5.3 ms（p99 10.0，最大 13.9） | 可以，但餘裕小 |
| 剪枝 | torch | 3,865 | 平均 8.5 ms（p95 9.8，最大 13.1） | 可以 |
| 剪枝 | numba | 3,806 | 平均 **0.49 ms**（p99 1.4，最大 2.0） | 餘裕約 30 倍 |

（同一台 2 核心 CPU 容器；torch 與 numba 的數字是不同時間量的。）`flybrain/lif_fast.py` 是用 numba 逐步照寫的 LIF（方程式、延遲、不應期都和 torch 版一樣），剪枝後每步約 30 微秒；代價是 Poisson 亂數來自 numpy，所以同一個種子的放電序列和 torch 版不同（統計上相同）。完整腦在 numba 下也能跑進 60 Hz，但它每步都要掃過 13.9 萬個神經元，換一台比較慢的比賽電腦餘裕就沒了；剪枝版沒有這個問題。GPU 沒量過。

**6.2 可以砍掉沒用到的神經元**（`flybrain/prune.py`）。只留「在你已重播的對戰裡放過電」的神經元，輸入與 DN 一定保留；用法：`replay.py --prune-cache cache` 或 `fly_eval.py --prune-cache cache`。在一場沒參與建立剪枝集合的對戰（lag，300 個決策）上量到：

- 最初的 2 場版：只剩 3,865 個神經元（2.8%）、約 20 萬條突觸；每個決策 0.136 秒 → 0.036 秒（約 3.7 倍，torch 版）。
- 保真度：剪枝版和完整版在**不同隨機輸入**下的差異，和完整版自己用兩個隨機種子的差異一樣大（逐 DN 相關 0.19 vs 0.20；戰術一致率 72% vs 71%）。也就是說剪枝的誤差淹沒在腦本身的隨機雜訊裡。
- **用 480 場重建（已做）**：用完整腦（numba）重播其中 48 場（每 10 場取 1 場）當「發現集」，保留至少在 3 場放過電的神經元（`keep_from_cache`，預設 `min(3, 場數)`）＝ **3,806 個**；要求 ≥1 場會留 13,307 個，≥5 場留 3,195 個。再用這個剪枝腦重播全部 480 場（370,039 個決策）。注意這只涵蓋收集時的飛行狀態；閉迴路時果蠅自己選的戰術可能把飛機帶到沒見過的狀態。`prune_eval.py` 可重跑保真度比對。
- **意外發現：失控（runaway）**。在 48 場發現集裡有 2 場，完整腦會進入自我維持的過度興奮狀態（DN 每窗放電約 300，正常約 79），和隨機種子有關。這時讀出層吃到的是雜訊。剪枝（≥3 場）把維持這個迴路的神經元一起拿掉了；另外 `FlyPolicy(runaway=300)` 加了保護：任何窗口 DN 放電超過 300 就重置腦並先飛 PURSUE。
- **重要發現**：同樣的輸入、不同隨機種子，每個 DN 逐窗的相關只有約 0.20，戰術一致率約 71%。輸出主要是 Poisson 輸入雜訊，這是讀出層學不好的重要原因。對策：增加每個特徵的輸入神經元數 k、拉長積分窗（例如 333 ms）、對多個窗口取平均。剪枝省下的算力正好拿來做這些。

**6.3 比賽迴圈怎麼接**（尚未實作）：每個 tick 呼叫 `brain.observe(feat, steps=17)`，把 DN 計數丟進最近約 250 ms 的環形緩衝，每 20 tick 用緩衝總和做讀出選戰術。注意：`fly_eval.py` / `replay.py` 目前只在每 20 tick 呼叫一次（jepa_brain 的 rollout 就是這樣呼叫 policy），所以讀出層必須用同樣格式的資料訓練；每 tick 版本還需要另外寫一個迴圈。

**6.4 懲罰**：jepa_brain 已經有 −3（輸）加擊殺分差（被擊落約 −7 到 −8）；官方 `combat_v3/config.json` 的參考獎勵有 `kill_bonus 30`、`loss_penalty 35`。問題是折扣 γ = 0.95 / 決策：懲罰只傳得到終局前約 7 秒，造成輸的開局決策感覺不到。`train_q.py --gamma 0.99 --death-extra 5 --loss-extra 3` 會用原本的獎勵重算回報（γ 改 0.99 約 33 秒視野，並在被擊落 / 點數輸的結尾加額外懲罰）。我驗證了：不加參數時完全還原原本的回報（差 0.0）。注意：
- 離線 R² 不能證明這樣更好，要靠閉迴路成對對戰。
- 死亡懲罰太重會讓它畏縮、不敢攻擊。官方參考計分權重是 attack_time 2000、over_g 1000、position 10、kill_base 1000（Host 的最終權重要以 Host 為準），訓練獎勵應該貼近實際計分。
- 「生物式」學習：果蠅自己的機制是蕈狀體裡 KC→MBON 突觸受多巴胺神經元調節（PPL1 負責懲罰、PAM 負責獎勵）。在機器學習裡，對線性讀出層來說，「資格痕跡 × 全域獎懲訊號」（三因子規則）等價於 TD(λ)。可以做的實驗是只讓 KC→MBON 的突觸可塑；**這我沒有實作也沒有驗證**。不建議去動其餘 1,500 萬條突觸的權重。

**6.5 訓練對手**：官方套件（`AirCombat_Train_Test`）只有控制器、FDM、規則與設定，沒有附對手 AI。你現有的 6 種對手是 `jepa_brain/opponents.py` 的 `ScriptedRed`：同一個凍結控制器配上固定或隨機的戰術。我量到的基線勝率：mix / breaker / level 各 10/10（沒有學習訊號），lag 7/10，lead 4/10，guide 2/10。`python league_weights.py <結果檔> --games 200` 會依勝率把場數分配給「還打不贏」的對手（保底每種 5%）。要更好的對手：
1. 把對手的參數隨機化（戰術切換時間、反應延遲、觀測雜訊、G 限制），避免只學會打固定腳本。
2. 對手庫放進你自己的歷代版本（PURSUE 基線、各版 SAC / JEPA 控制器、舊的果蠅讀出層），用上面的分配法抽樣（優先抽打不贏的）。
3. 留 1 到 2 種對手完全不參與訓練，只拿來當最終考試。
4. 其他隊伍很可能也用官方同一個控制器加不同戰術策略，所以「同一個控制器 + 不同戰術策略」的對手分布最貼近真實比賽。

**6.8 為什麼兩個圈子轉不完、為什麼 high yo-yo 沒用（10/17 實測）**

用 `fly_acmi.py --telemetry` 把 PURSUE 對 PURSUE（lag，種子 950000）整場記下來：距離小於 914 m 且在攻擊窗內的時間只有 **3.5%**，機鼻對準視線的角度**從未進到 1°**。兩機是平面的兩圈 rosette：平均 2.4 G（最大 5 G）、俯仰角只有 0–6.6°、5 分鐘掉 345 m，每約 48 秒交會一次，交會時機鼻離視線還有 80–110°。也就是說，不是「不敢攻擊」，而是純追擊的幾何本身就轉不進 1° 錐。

我另外測了「近距離時承諾做 high yo-yo」的手寫規則（`yoyo_test.py`；36 場成對，lag / lead / guide 各 12）：yo-yo 長度 3 / 9 / 15 個決策分別是 14–22 / 8–28 / 8–28，base_t3 是 28–8，對 guide 是 0–12。**盲目的 high yo-yo 比不做還差**；它不是壞戰術，而是用在錯的時間點（對手沒有 overshoot 時等於把位置分送出去）。

**6.9 新做法的核心：分支反事實標籤（`branch_labels.py`）**

之前的離線回報學不到東西（R² ≈ 0），因為資料只是「這個局面最後好不好」，看不出「是哪個戰術造成的」。這次在一場正在進行的對戰中，每隔幾個決策把整個模擬器用 `os.fork` 複製成 8 份（PURSUE、7 個戰術、1 份對照用的微擾動），每一份從**完全相同的局面、對手、亂數**出發，分別飛「戰術 k 兩秒（6 個決策）、再回到 PURSUE」共 15 秒，然後讀 judge 的優勢分差。因此各選項之間的差別一定是選項造成的。

- 驗證：模擬是確定性的；對照擾動（第 9 份）與 PURSUE 差約 1e-3 分，PURSUE 分支與親程序自己的未來一模一樣（`--check`）。
- 資料：36 場（guide / lag / lead 各 10 場，mix / breaker / level 各 2 場；種子 800000–800009）共 2,110 個近距離（< 3,500 m）局面，每個局面都有 7 個選項的真實優勢（judge 分 / 15 秒）。
- 結果（近距離、每局面的平均優勢，相對於 PURSUE）：

| 對手 | LEAD | LAG | BREAK_IN | BREAK_OUT | HIGH_YOYO | LOW_YOYO | EXTEND |
|---|---|---|---|---|---|---|---|
| 全部（1,769 個局面，30 場） | **+11.7** | +0.7 | −225 | −425 | −147 | −69 | −151 |
| guide | **+18.5** | +2.0 | +12.3 | −100 | −53 | −11 | −72 |
| lag | **+25.5** | −2.8 | +7.8 | −88 | −53 | −13 | −65 |
| lead | −11.7（中位數 +10.8） | +4.3 | −7.7 | −220 | −85 | −60 | −159 |
| breaker | **+73.3** | −19.8 | −95 | −308 | −154 | −42 | −233 |

LEAD（瞄準對手前方一個提前量）在 guide / lag 約 88–97% 的近距離局面比 PURSUE 好（超過雜訊門檻 +5 分）；對 lead 型對手是兩面刃（59% 的局面變好、28% 變差）；BREAK_OUT / HIGH_YOYO / EXTEND / LOW_YOYO 幾乎永遠比 PURSUE 差。「事後諸葛」最佳選項平均約 +103（2,110 個局面）到 +113 分（30 場），且每個局面的最佳選項各不相同，這是學習有空間的上限（含最大值偏誤，偏樂觀）。

**怎麼讀**：(1) 鏡像與弱到中等的腳本對手（guide、defender、pp0–pp5、ctl:*）上 ≥ 23/24 的勝率是穩定可重現的（lag 以外），在兩批獨立種子（1010000、1030000）上都一樣；(2) 這個優勢主要來自「近距離改變戰術、打破僵局」（6.17 的隨機對照已經說明），而不是我們擁有一個高明的空戰判斷；(3) 這個優勢在 lead 型、lag 型、SAC 型對手上不存在或很小，那些是 `base_t3` / `tuned` 本來就會贏或本來就贏不了的對手。

**6.22 結論與建議（10/19）**

**兩個候選，都是「近距離才介入的選項戰術員」，底都用你的 tuned 追擊，差別只在決策頭：**

| | A. ridge v1（`opt_ridge:tuned`） | B. MLP v4（`opt_mlp:tuned`） |
|---|---|---|
| 模型 | 54 × 7 個權重（原始特徵 + EMA） | 2×64 relu 集成 × 5，約 4 萬個權重 |
| 訓練標籤 | 30 場 | 103 場（含自對戰 16 場、lead 10 場） |
| 腳本對手池（確認種子，216 場） | 209-7，0 碰撞輸，分差 2,992 | 209-7，0 碰撞輸，分差 4,154 |
| lead 型對手 | **22-2**（tuned 23-1） | 18-6 |
| sac:25.6M | 14-10 | 15-9（tuned 13-11；都沒有實質改善） |
| 對「也會戰術」的對手 | 對 MLP v3 12-36、對 MLP v4 21-27 | 對 v3 35-13、對 ridge v3 34-14，對 ridge v1 27-21（不顯著） |
| 單次 `act()` | 0.25 ms（決策 tick 0.38 ms） | 0.24 ms（決策 tick 0.39 ms） |
| 可攜版與 harness 逐場一致 | 是 | 是 |

**我的建議**：

1. **預設用 A（ridge v1）。** 它最簡單、沒有已知弱點（SAC 以外所有類型的勝率都 ≥ 83%，確認種子上最低的格子是 lag 21/24），而且三批獨立種子的結果都一樣。在腳本對手上 B 沒有多贏場次，只多了分差。
2. **如果有理由相信對手會做戰術切換（例如對方隊伍也在 TacticalPilot 上疊決策層），改用 B。** 對手也會戰術時，ridge v1 有被 MLP 類的頭剋制的證據（12-36），B 沒有；代價是 lead 型對手少贏約 4 場／24。
3. **BO3 賽制下的用法（只是建議，沒有驗證）**：你的 bfm 基準文件提到輪與輪之間可以換設定。可以第一局用 A；若第一局顯示對手在近距離明顯切換戰術（持續打破你的 PURSUE），第二局換 B。若對手是 SAC 25.6M 型的遠距離逃離者，兩個頭都沒有優勢（見下），可以回到 plain `tuned`。這個切換規則我沒有在 harness 上預跑過。
4. **果蠅 DN 版不建議上線**：總勝場和 A、B 一樣，但 lead 弱點（15-9、2 場碰撞輸）可重現，還要多帶 numba、剪枝連結體與 2–3 ms 的決策成本；沒有證據顯示連結體提供原始特徵以外的資訊（6.16-3）。它唯一的特色是 SAC 25.6M 較好（三批都是 17–18 勝／24，後兩批對 base_t3 逐場 13 對 2），這個優勢和 lead 弱點大致抵銷，且我沒能把 SAC 優勢歸因到連結體本身。

**真正有貢獻的東西（誠實版）：**

- (a) **近距離不要一直純 PURSUE（打破鏡像僵局）** 佔了 guide / lag / 鏡像局勝場的絕大部分——連「完全不看狀態的隨機戰術」都有 141 勝（6.17）。
- (b) **學習的貢獻**：在 lead 型對手上，學到的頭不會被隨機戰術那樣破壞（15-3 對 6-12）；平均分差從 1,449（隨機）提高到 2,800–4,200；**當對手也是戰術員時，隨機戰術只有 10.9%、學到的頭 50–70%（6.20）**。
- (c) **反事實分支標籤本身**（`branch_labels.py`）是可重用的訓練訊號：每場約 3 分鐘（2 核心），可以對任何新對手（包括另一個戰術員）補標；第二輪 DAgger 證實對 MLP 有用，對線性頭沒用。
- (d) 連結體：沒有獨立貢獻的證據。

**沒有解決的事**：sac:25.6M（遠距離尾追）沒有進步，也沒有退步；lead 型對手上 MLP / DN 比 ridge 弱；所有結果都是本地 judge 加上腳本 / 舊 checkpoint 對手；沒有 Host 驗證。

1. **Host 實機驗證**（唯一阻擋上線的項目）：把 `portable\fighter_opt.py` + `portable\player_fighter_opt.py` 放在 `fighter.py` 旁邊，`--profile opt_ridge:tuned`，先跑 shadow（只記錄戰術員會選什麼、不控制），再 10 場實機。看 (a) 每決策延遲；(b) `act()` 實際呼叫次數對 sim tick 的比例（影響 20 次一決策的節奏）；(c) Host 的攻擊 tick 判定與本地 judge 是否一致。

3. 若要繼續提升：下一個高價值的標籤來源是**你 campaign 裡真正會打的對手**（不是我用的腳本），因為腳本對手池已經飽和，而自對戰顯示標籤分布決定頭的強弱。
4. 不建議再投入：SAC 25.6M 遠距標籤（事後最佳優勢 ≈ 0）、更複雜的非線性頭（對腳本池沒有增益）、EMA 感覺通道、果蠅 + 原始特徵混合頭、調高 tau、ridge + MLP 平均——這些都做過，沒有閉迴路收益（6.16、6.20b）。
