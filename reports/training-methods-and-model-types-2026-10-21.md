# 空戰 AI:訓練方法、模型類型與補丁修改原則(公開版,2026-10-21)

> 這是完整內部文件的公開精簡版。刻意不含:私有 IP、報名資料、控制程式原始碼、常數與門檻數值、針對特定對手類型的戰術細節、賽間切換決策表。
>
> 每一條都標來源:**文獻**(作者打開頁面確認過)、**實測**(作者自己的專案紀錄,本地模擬器與本地 judge,不是主辦方認證)、**推測**(作者的推論,尚未驗證)。

## 一頁摘要

- 現況:主力是「規則式追擊 + 防撞盾 + 演化策略調出的一組常數」。本地裁判下表現最好,但對手與訓練同屬一族腳本,所以勝率可能高估對真實對手的表現。
- 神經網路 / 強化學習:試過幾條路(SAC 殘差、小型模仿網路、連結體選擇器等),專案紀錄中沒有任何一條明確勝過主力。
- LLM、線上搜尋(MCTS)放進 60 Hz 迴路:沒找到經驗證的空戰證據;每個決策只有約 16 ms,屬推測性論證。
- 剩下時間最值得做的:用不同族的對手與新種子重新驗證、彩排賽間切換、用最終打包版再做一次官方 Host 測試、截止前凍結。

## 一、訓練方法全盤點

「訓練」指把模型裡的數字調到表現更好的過程。調的方式決定了方法的名字。以下依綜述分類,不是全部。

| # | 類別 | 做法 | 空戰文獻裡的例子 |
|---|---|---|---|
| 1 | 不訓練、人工設計 | 專家寫死規則或行為樹 | 行為樹、行為樹網路、模糊樹(綜述 [arXiv 2404.13954](https://arxiv.org/abs/2404.13954)) |
| 2 | 搜尋參數 | 隨機改一批參數,留下表現好的,重複 | 演化策略 ES、遺傳演算法 GA、NEAT、遺傳模糊樹 |
| 3 | 模仿學習 | 給專家示範,讓模型模仿 | 行為複製 BC、DAgger、逆強化學習(綜述只有描述) |
| 4 | 強化學習(單一代理) | 在模擬器裡反覆試錯,靠獎勵學習 | SAC、PPO、DDPG、A2C、DQN(綜述指出 DQN 只見於超視距情境) |
| 5 | 多代理強化學習 | 多架飛機合作設計 | QMIX、MADDPG、HAPPO、HASAC;本比賽是 1 對 1,直接用不上 |
| 6 | 階層式強化學習 | 上層選行為、下層執行 | PHANG-MAN、階層式 PPO |
| 7 | 訓練技巧 | 疊在其他方法上 | 自我對弈、歷史對手池、課程學習、獎勵塑形、群體訓練 PBT |
| 8 | 線上搜尋與規劃 | 每一步先模擬幾種未來再選 | MCTS、動態規劃 |
| 9 | 預測型表徵學習 | 先學把狀態壓成摘要 | JEPA(自監督表徵,不是控制方法本身) |

### 各類重點

- **1 手寫規則**:可讀、可逐行驗證、延遲極低,但上限取決於人想得到多少情境。**實測**:主力就屬於這類。
- **2 搜尋參數**:不需要算梯度。OpenAI 的論文宣稱 ES 可以隨 CPU 數量極好地擴展,不需要反向傳播([arXiv 1703.03864](https://arxiv.org/abs/1703.03864));該論文也指出對動作頻率、延遲獎勵不敏感。**實測**:作者用 (1+λ)-ES 調一組追擊常數,共兩輪;確認階段使用另一批種子。風險是調到「剛好打得贏同一族對手」。
- **3 模仿學習**:BC 的缺點是訓練資料只有專家走過的狀態,實際飛時會走到沒見過的狀態,小錯誤會越滾越大;DAgger 讓學生自己飛,再請專家重新標註,理論上把誤差從 O(T²ε) 降到 O(Tε)(CS224R 筆記);缺點是需要專家隨時能答。**實測**:作者試過的小型神經網路版本見第 4 類與第二節,都沒有明確勝過規則主力。
- **4 強化學習**:單一代理 + 隨機策略 + 熵獎勵探索的 SAC 在空戰論文中常見。**實測**:官方 SAC 範例在作者的測試環境裡大多自己墜地;SAC 殘差(在規則輸出上加修正量)從沒贏過純規則;官方中途 checkpoint 有「被追尾時處理不好」的已知弱點。
- **5–6 多代理與階層式**:階層式最值得看。PHANG-MAN([arXiv 2105.00990](https://arxiv.org/abs/2105.00990)):上層約 10 Hz 的策略選擇器 + 三個約 50 Hz 的專長策略,下層訓練後凍結,再訓練上層;訓練對約 30 種對手並加入自我對弈,在三個評估對手上 191 勝 57 敗,在 DARPA AlphaDogfight 決賽拿第二名。六自由度階層式 PPO([arXiv 2212.03830](https://arxiv.org/abs/2212.03830)):內層控制器 + 外層策略 + 自我對弈對手池;比較了不同決策間隔,間隔拉長到 4.0 秒時會被擊落。Selmonaj 等([arXiv 2309.11247](https://arxiv.org/abs/2309.11247)):階層式 MAPPO 風格,在自製 2D 模擬器上。**實測**:作者做的近距離戰術選擇器沒有救回已知弱點。注意:PHANG-MAN 的下層是訓練出來的策略,作者的下層是手寫規則,兩者不能直接比較。
- **7 訓練技巧**:自我對弈與對手池、課程學習、獎勵塑形、PBT([arXiv 1711.09846](https://arxiv.org/abs/1711.09846))。Heron Systems 贏得 AlphaDogfight 並 5 比 0 擊敗人類飛行員;報導說工程師表示經歷至少 40 億次模擬;我打開的報導沒有寫演算法細節。**推測**:這個模擬量和單人、單張消費級顯卡、約兩週的資源不在同一個量級。
- **8 線上搜尋**:MCTS 空戰論文([arXiv 2009.08807](https://arxiv.org/abs/2009.08807))在簡化 2D 環境(只有左轉、直飛、右轉)中,當我方機動性較佳時贏約 70%;我打開的頁面沒有報告決策延遲。**推測**:60 Hz 迴路每步約 16 ms,要在預算內搜尋大概得用簡化模型,風險是簡化模型與真實模擬器有落差。作者沒有這條路的實測紀錄。
- **9 預測型表徵(JEPA)**:自監督表徵方法,不是控制方法本身。沒有找到經驗證的「世界模型(如 Dreamer)用在空戰」的證據。

## 二、模型類型全盤點(十類)

「模型」指每個決策時刻,決定下一步動作的那個東西。

1. **手寫規則 / FSM / 行為樹**。**實測**:主力屬於此類(規則 + 一組可調常數)。
2. **控制律與 PID 內迴路**:把想要的航向、坡度換算成舵面指令。PHANG-MAN 與六自由度階層式 PPO 都把低層控制和高層策略分開。
3. **線上搜尋 / MCTS**:見上。無實測紀錄。
4. **小型神經網路(RL 或 BC 訓練)**:綜述指出神經網路約出現在四分之三的研究中。**實測**:本地最佳的純神經網路版本約 87%,主力約 93%,但批次與種子不同,不能當嚴格比較。
5. **序列 / 記憶網路(LSTM、GRU、注意力)**:綜述引用 Bae 等人的結果,在部分可觀測下 LSTM 有大幅進步。無實測紀錄。**推測**:要看主辦方給的觀測是否本來就包含完整狀態;若已完整,記憶的邊際效益可能有限。
6. **階層式選擇器**:見上。
7. **世界模型 / JEPA**:見上。
8. **大型語言模型(LLM)**:沒有找到經驗證的「LLM 以 60 Hz 直接操控戰鬥機」的證據。**推測**:LLM 單次推論通常要數十到數百毫秒,放進 60 Hz 迴路不合理;比較合理的用法是賽前離線讀日誌、分析失敗局、提出規則修改建議,再由人驗證。**實測**:作者的輕量線性選擇器每次推論約 0.25 ms,供對照量級。
9. **神經形態 / 脈衝網路 / 連結體**:作者打開的 SNN 論文是用演化法訓練脈衝網路控制飛艇高度,沒有量化能耗數據,與空戰沒有直接關係。**實測**:作者把果蠅連結體(FlyWire)修剪成約 4,758 個神經元用於近距離戰術選擇;與打亂連線的對照組相比沒有獨立貢獻;非劣性檢驗通過(250-14 對 241-23,差 +3.4 個百分點,信賴區間 [−0.4, +7.2]),但在某類對手上弱點明顯。結論:不比主力差,但不能說連結體本身讓它變強。
10. **比賽層的元策略**:兩局之間有 3 分鐘空檔,可以更換 AI 或演算法。作者每個版本備有獨立啟動檔。**尚未彩排**。

### 比較(推測性分級,非量測值)

| 類型 | 資料需求 | 訓練運算 | 每步延遲 | 主要風險 |
|---|---|---|---|---|
| 1 規則 / FSM / BT | 低 | 低 | 極低 | 受限於人的設計 |
| 2 控制律 / PID | 低 | 低 | 極低 | 參數不當會失穩 |
| 3 線上搜尋 | 低(但需要模型) | 低 | 高 | 16 ms 預算內跑不完 |
| 4 小型 NN | 高 | 高 | 低 | 過擬合訓練對手、自撞 |
| 5 LSTM 等 | 高 | 高 | 低到中 | 訓練不穩、難除錯 |
| 6 階層式選擇器 | 中 | 中 | 低 | 切換抖動、決策間隔過長 |
| 7 世界模型 / JEPA | 高 | 高 | 視用法 | 空戰上缺少驗證證據 |
| 8 LLM | 低到中 | 低 | 極高 | 延遲遠超 16 ms |
| 9 SNN / 連結體 | 中 | 中 | 低 | 沒有證據顯示優於一般網路 |
| 10 元策略 | 低 | 低 | 無(賽間) | 對手類型判斷錯誤 |

## 三、補丁修改的通用原則

「補丁」指疊在基礎追擊上、可以單獨開關或替換的修改(防撞盾、調參常數、選配的戰術選擇器等)。

1. **一次只改一件事**,先寫下一句假設,同時改兩件事就分不出是哪個起作用。
2. **改來源,不要改產物**:規則與常數改在來源檔,再用產生腳本重新生成可攜式套件;自動產生的檔案不要手動編輯。
3. **等價性檢查**:用合成觀測值確認打包版和研究版輸出一致,差異必須為 0。
4. **UDP 迴路測試**:用假的 Host 確認能連線、能收到狀態、能回傳動作。
5. **啟動自檢**:每次啟動都跑自檢,不通過就不要上場。
6. **新種子成對驗證**:用沒用過的種子跟目前主力成對比較,看信賴區間,不要只看勝負。
7. **整包重建**:打包流程會重算 SHA 清單,不能直接把改過的檔案塞進舊壓縮檔。
8. **官方 Host 測試**:連上官方 Host 跑一次,確認狀態正常、沒有碰撞。

驗收門檻(作者的建議,不是規定):0 碰撞、0 超 G;對主要對手族不比主力差;新種子成對的信賴區間不包含明顯退步。

**紅線與退路**:控制程式在截止日前凍結,並留彩排時間;不要覆蓋舊啟動檔,新版本用新名字,賽間 3 分鐘內要能退回已驗證版本;每次修改都記錄「改了什麼、假設、種子、成績、是否過門檻」,沒記錄的結果一律當作沒做。

## 四、剩下時間的建議(推測性)

1. 確認報名已完成。
2. 用不同族的對手與新種子重新驗證主力(這是目前最大的資料缺口:訓練與驗證用同一族腳本對手,真實對手是其他隊伍的 AI)。
3. 用最終打包版再做一次官方 Host 測試。
4. 彩排賽間 3 分鐘切換流程。
5. 不開新的大型 RL 訓練、不做第三輪 ES、不把 LLM 或 MCTS 放進 60 Hz 迴路。
